  • 作成者：丹野美紗

2分

2. 誰のためのアプリか

想定ユーザー

  • 小規模農園・直売の生産者
  • 新鮮なブルーベリーを買いたい人

困りごと

  • 電話・LINEだと在庫が追いづらい
  • 紙・Excelだと履歴がばらばら

解決したいこと：注文・在庫・進捗を Web で見えるようにする

3

3. アプリの概要

商品を探してカートに入れ、配送先入力のあと Stripe で支払い、注文を確定できる簡易 EC。管理者は商品・在庫・注文・管理者追加も扱えます。

  • 商品・カート・送料・Stripe テスト決済
  • 郵便番号住所検索・レビュー・お気に入り
  • 管理者追加／削除・キャンセル／返品・パスワード再設定

4

4. 既存の方法との違い

これまで

  • 電話・LINE・紙・Excel
  • 手計算の送料

このアプリ

  • Webで一覧〜決済まで一連
  • 在庫・ステータス・Stripeテスト

強み：最小構成で一連の購入体験　／　限界：常時サーバー・本番決済・実メールはこれから

5・1分

5. マネタイズ（案）

  • 払うのは主に生産者・直売運営
  • 消費者は基本無料
  • 収益案：月額 / 手数料 / 導入支援

無料＝閲覧・注文（テスト決済）　｜　有料候補＝実メール・本番決済・複数店舗

6・3分

7・デモ

7. デモの流れ

買う人

  1. ログイン → 検索 → 詳細
  2. カート → 郵便番号検索
  3. Stripe で支払い完了

管理者

  1. ログイン → 在庫編集
  2. 注文ステータス変更
  3. 管理者追加／問い合わせ

デモURL：https://freshberrymarket.com/（Tunnel 起動時）

8・2分

8. 工夫したところ

  • Stripe Checkout と注文確定のつなぎ（二重注文防止）
  • 在庫の減算と戻し／郵便番号から住所自動入力
  • CSRF・ハッシュ・管理者追加削除・パスワード再設定

9

9. 苦労したところ

  • 決済成功後にだけ注文を確定する流れ
  • CSRF 対応と、お気に入り導線の見やすさ
  • ドメイン公開（Tunnel）とローカル起動の関係

学び：現象 → 原因の場所 → 再現、の順で切り分ける

10・1分

  • 学び：検索〜決済〜公開まで一気通貫で自作した経験
